# AI Studio connection troubleshooting

Android INTERNET permission is present; HTTPS only. AI Studio requires a valid provider API key (not just ChatGPT/Gmail login). Choose provider, copy official key page, enter the key, fetch available models or enter an eligible model manually, press Test connection. This sends only a fixed OK prompt (may use quota). After test succeeds, enter/review actual prompt and tick consent; Send becomes available. OpenRouter defaults to openrouter/free; it still needs a key and is quota-limited. Gemini uses native generateContent and models.list filtered for generateContent capability. Ollama is desktop-only and must already be running. Keys are held only within the AI Studio screen in memory; switching provider preserves its key/model during that screen session. No key saved to disk. HTTP errors have explicit remediation; raw error bodies are not displayed. Mock tests do not establish real account or model access.
AI Studio remains mounted while navigating other tabs; new inspector drafts update the prompt without destroying provider state. Keys remain only in app memory until exit or Clear session API keys. New code requires renewed consent; stale responses to replaced drafts are not displayed. Only AI stays mounted to limit memory.
